# Framework integrations

These adapters implement the same trust boundary:

1. The customer backend authenticates the viewer.
2. It resolves the viewer's email from its own trusted auth/session state.
3. It checks whether that viewer may watch the requested content.
4. The browser supplies a stable random device ID generated by the official SDK.
5. The customer backend calls `/v1/playback/sessions` with its secret API key, trusted email,
   device ID and viewer request context.
6. Unpirator creates the protected session and, when enabled, renders the viewer email in the
   dynamic watermark.

The browser never supplies trusted viewer identity and never receives the customer's Unpirator API
key. Unpirator stores only the playback/security identity linkage it needs; it does not mirror the
customer's user profile or password database.
